# /restart

呼び出されたら、状況の分析・報告・確認は行わず、この会話で直前まで取り組んでいた作業をそのまま続きから再開する。

- 根拠にするのはこの会話自身の直近のやり取りのみ。`git status`・`~/.claude/plans/`・`文書/日記.md`等を横断的に調べて中断状態を推測する処理は行わない。「作業を再開して」と都度手で指示するのが面倒なのでショートカット化したのがこのスキルの動機であり、状態解析はその目的に反する。
- 複数の作業が並行して進んでいたように見えても、いちいち「どれから再開しますか」とは聞かない。直近の会話で最後に取り組んでいた作業をそのまま続ける。
- 例外として、会話履歴から再開すべき作業が全く読み取れない場合（例: セッションの最初のメッセージとして`/restart`が呼ばれた場合）のみ、その旨を伝えて何を再開すべきか指示を仰ぐ。
- 再開する作業が、コミット・push・リリースなど外部に影響する操作の途中だった場合も、その操作について会話内で既に得ている承認の範囲内でのみ続ける。承認を得ていない操作は、再開しても実行せず確認を取る。
